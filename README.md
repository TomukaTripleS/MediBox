# MediBox

Застосунок для обліку домашньої аптечки зі спільним доступом для сім’ї.

## Опис

MediBox — вебзастосунок для обліку домашньої аптечки зі спільним доступом для членів сім’ї. Він допомагатиме бачити наявні ліки, контролювати їхні залишки та отримувати нагадування про наближення терміну придатності. Застосунок призначений для людей, які хочуть зручно організувати домашні запаси ліків і підтримувати актуальну інформацію про них.

## Ролі

У повній версії проєкту передбачено такі можливості ролей:

- **Власник** — створює аптечку, керує її налаштуваннями, запрошує та видаляє учасників. Може додавати й редагувати препарати, оновлювати залишки, реєструвати використання та видаляти аптечку.
- **Учасник** — переглядає й шукає препарати, додає та редагує записи, оновлює залишки й реєструє використання. Має доступ до історії операцій і сповіщень, але не може керувати учасниками або видаляти аптечку.

Роль визначається окремо для кожної аптечки: користувач може бути власником однієї та учасником іншої. Доступ до аптечки мають лише авторизовані користувачі, які входять до її складу.

## Основний функціонал

Запланований функціонал повної версії:

- Реєстрація та вхід до облікового запису.
- Створення аптечок і спільний доступ за запрошенням.
- Додавання та редагування препаратів із зазначенням назви, форми, кількості, одиниці обліку й терміну придатності.
- Окремий облік упаковок із різними термінами придатності.
- Пошук препаратів за назвою.
- Реєстрація використання ліків з автоматичним оновленням залишку.
- Перегляд історії операцій.
- Сповіщення про наближення терміну придатності та малий залишок.

## Особливість проєкту

MediBox передбачає автоматичні сповіщення всередині застосунку. Система регулярно перевірятиме терміни придатності й залишки препаратів та створюватиме нагадування для учасників відповідної аптечки. Повторні перевірки не повинні дублювати нагадування про ту саму подію.

Спільний облік також потребує узгодженого оновлення даних: під час реєстрації використання система перевірятиме доступну кількість, зменшуватиме залишок і зберігатиме операцію в історії. Це допоможе уникати від’ємних залишків і помилок під час одночасної роботи кількох учасників.

## Реалізовані можливості

Реалізовано API аптечок на Django REST Framework і SQLite з JWT-автентифікацією. Власник створює аптечку, змінює назву й учасників та видаляє її. Учасник може переглядати аптечку й змінювати назву. Сторонні користувачі не мають доступу.

Облік препаратів, історія використання, запрошення та сповіщення про терміни придатності й малі залишки заплановані на наступні етапи.

## Запуск

Потрібен Python 3.12+.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

У `.env` замініть `replace-with-generated-secret-key` власним випадковим ключем. Згенерувати його можна командою:

```bash
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

Змінні середовища:

| Змінна | Значення |
| --- | --- |
| `DJANGO_SECRET_KEY` | Обов’язковий секретний ключ; без нього або із заглушкою застосунок не запуститься |
| `DJANGO_DEBUG` | `1` для локальної розробки, `0` для вимкнення налагодження; за замовчуванням `0` |
| `DJANGO_ALLOWED_HOSTS` | Дозволені хости через кому, локально `localhost,127.0.0.1` |

Файл `.env` автоматично завантажується через [python-dotenv](https://github.com/theskumar/python-dotenv). Змінні, уже задані в середовищі, мають пріоритет. `.env` не потрапляє до Git; `.env.example` містить лише заглушки. Для SQLite пароль бази даних не потрібен.

Після налаштування `.env`:

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

У Windows активація: `.venv\Scripts\activate`, копіювання прикладу: `copy .env.example .env`. Користувачі створюються командою `createsuperuser`; для перевірки спільного доступу створіть кількох. Їхні ID можна переглянути командою:

```bash
python manage.py shell -c "from django.contrib.auth import get_user_model; print(list(get_user_model().objects.values('id', 'username')))"
```

## API

Базова адреса: `http://127.0.0.1:8000/api/`.

- POST `token/` з `{"username":"student","password":"your-password"}` повертає `access` і `refresh`.
- POST `token/refresh/` з `{"refresh":"..."}` повертає новий `access`.
- Для аптечок потрібен заголовок `Authorization: Bearer <access>`.

| Метод | Шлях | Дія |
| --- | --- | --- |
| GET | `kits/` | Список доступних аптечок |
| POST | `kits/` | Створення |
| GET | `kits/{id}/` | Перегляд |
| PUT / PATCH | `kits/{id}/` | Редагування |
| DELETE | `kits/{id}/` | Видалення власником |

Приклад JSON для створення: `{"name":"Домашня аптечка","members":[2]}`. Назва обов’язкова, до 150 символів; учасники — необов’язковий список ID користувачів. Власник призначається автоматично. Змінювати список учасників може лише власник.

## Документація API

[Swagger UI](http://127.0.0.1:8000/api/docs/) · [OpenAPI-схема](http://127.0.0.1:8000/api/schema/)

У Swagger натисніть **Authorize** і вставте access-токен без `Bearer`. Для завантаження Swagger UI потрібен інтернет. Експорт і перевірка схеми:

```bash
python manage.py spectacular --file schema.yml --validate --fail-on-warn
```

## Логування

Логи виводяться в консоль і записуються у файл `logs/medibox.log` з часом, рівнем і назвою логера. Папка створюється автоматично та не потрапляє до Git. Коли файл досягає 1 МіБ, починається новий; зберігаються до трьох попередніх файлів (`medibox.log.1`–`medibox.log.3`).

Успішне створення, редагування та видалення аптечки записуються на рівні `INFO`. Відхилені запити (невалідні дані, відсутня автентифікація, недостатні права або відсутня аптечка) — на рівні `WARNING`.

Логи операцій містять лише ID аптечки й користувача, логи відмов — назву дії, ID користувача та HTTP-статус. Тіла запитів, назви аптечок, паролі й токени не записуються.

## Тести

Перед запуском установіть залежності й налаштуйте `.env`, як описано вище.

```bash
python -m pytest
python -m pytest --cov --cov-report=term-missing
```

Фікстури в `tests/conftest.py` створюють користувачів, аптечку та API-клієнти. Перевіряються CRUD, права доступу, неправильні дані, JWT і документація API. Тестова база створюється автоматично.

Результат: **40 тестів, покриття 98%** коду `config` і `kits` без міграцій та WSGI. Звіт виводиться в термінал; за умовою завдання його потрібно скопіювати в опис Pull Request. Повторно переглянути звіт після запуску тестів з `--cov`:

```bash
python -m coverage report
```
